总体评价：架构和核心逻辑是健康的（模块分层、间隔重复闭环、due 下标清单都做得对）。 主要风险集中在数据解析的健壮性——csv 一旦出现空行、BOM、脏数据，程序可能直接崩溃或静默吞掉词库。 建议按路线图先修 P0 三项，再补 P1。

一、发现的问题（按严重度排序）

P0 崩溃#1parseLine 遇空行/脏数据直接崩溃wordbank.cpp:4-21
现象csv 末尾空行、缺字段的行、或手误输错的脏行，会让 stoi("") 抛 std::invalid_argument 异常，程序直接崩溃。
原因line.find(',') 找不到逗号时返回 npos（超大值），substr 拿不到预期片段，stoi 收到空串。且 parseLine 永远返回 true，从不拒收坏行。
建议解析前校验：pos == string::npos 直接 return false；每个字段 substr 后检查非空；stoi 包 try-catch 或用 from_chars。空行在 loadWords 里 if (line.empty()) continue;。
P0 坏数据#2UTF-8 BOM 未处理，编辑器保存即坏首行wordbank.cpp loadWords
现象用 VS 等编辑器保存 csv 会写入 3 个隐藏字节 EF BB BF，第一行第一个词（english）带上看不见的前缀，查重、删除、匹配全部失败。
建议loadWords 读每行时检测并跳过 BOM：if (line[0]==0xEF && line[1]==0xBB && line[2]==0xBF) line = line.substr(3);——一劳永逸，任何编辑器都不怕。
P0 静默失败#3loadWords / saveWords 返回值被忽略ui.cpp:17 · console.cpp:19
现象loadWords(csvPath, words) 的 bool 返回值从不检查——文件丢失/打不开时静默得到空词库，用户看到"今天没有要背的词"误以为数据丢了。
建议调用处检查返回值，失败时明确提示"词库文件读取失败：路径"并退出；saveWords 失败也应提示（磁盘满/只读时数据会悄悄丢）。
P1 功能#4remove 无法删除词组（空格截断）console.cpp:72
现象cin >> target 遇空格即停——想删 checks and balances 只会匹配到 checks，永远"没找到"。
建议和 add 一样换 getline（记得先 cin.ignore() 清残留回车）。
P1 交互#5未知命令行参数静默退出word_trainer.cpp:28
现象敲 word-trainer.exe --abc 直接无声退出，用户不知道发生了什么。
建议加 else 分支打印用法：用法: word-trainer [--manage] [--quiz]。
P1 资源#6LoadFontEx 后未 UnloadFontui.cpp:38
现象字体加载后没有 UnloadFont(zh)——虽然退出时系统回收，但资源管理不规范，将来加"重载字体"功能会泄漏。
建议循环退出后、CloseWindow() 前补 UnloadFont(zh)。
P1 路径#7字体字库路径硬编码 + 未判空ui.cpp:35
现象C:\Users\36779\OneDrive\Desktop\common_chars.txt 写死——换机器、换用户名、换目录直接找不到；LoadFileText 返回 nullptr 时未检查，LoadCodepoints 会拿到空指针。
建议字库文件随程序分发（放到源码目录或资源目录，用 cppDir() 拼路径），并判空提示。这是你 words.csv 修好的同款问题，字体也该享受同等待遇。
P2 规范#8头文件里 using namespace stdword.h:3
现象头文件写 using namespace std; 会把 std 全部塞进每个 include 它的文件的全局命名空间——名字冲突的定时炸弹。
建议头文件里写 std::string 全限定；using 只放在 .cpp 里。
P2 规范#9parseLine 的 pos-0 怪写法 + 无字段数校验wordbank.cpp:7
现象substr(0, pos-0) 的 -0 是无意义的装饰写法；且没有校验一行到底有几个字段。
建议写成 substr(0, pos)；解析完检查 5 个字段齐全，缺一个就 return false。
P2 隐患#10两份 words.csv 不同步CMakeLists.txt:24
现象configure_file 把 csv 复制到构建目录，但程序 cppDir() 读的是源目录——构建目录那份永远是"构建时的快照"，改词后两边不一致，容易让人困惑"读的是哪个"（你今天就踩到了）。
建议二选一：删掉 configure_file（程序统一读源目录）；或程序改成读 exe 目录（argv[0] 定位）并保留复制。
P2 规范#11头文件依赖传递（不自给自足）wordbank.h:2-4
现象wordbank.h 用了 string/vector/fstream 却没 include，靠 word.h 碰巧带进来——将来 word.h 一改，编译就断。
建议每个头文件 include 自己用到的所有头（<string> <vector> <fstream>）。
P2 重复#12csvPath 拼接逻辑重复两处ui.cpp:16 · console.cpp:17
现象两个文件各自写一遍 (fs::path(cppDir()) / "words.csv").string()。
建议在 path_util 加 wordsCsvPath() 返回统一路径——以后换存储位置只改一处。
P3 待办#13V2.0 答题模式未实现word_trainer.cpp · quiz 缺失
现状需求文档已定（7 步），main 里还没有 --quiz 分支，CMakeLists 也没有 quiz.cpp。
建议按 word-trainer-V2.0需求与开发步骤.md 逐步实现；登记新文件记得改 CMakeLists 的 add_executable。
P3 环境#14控制台中文输入乱码（环境问题）console.cpp:60
现状旧控制台（conhost）在 65001 下读中文 IME 输入会错位，导致 add 的中文写坏（已通过记事本编辑 csv 绕开）。
建议长期方案：Windows Terminal 运行，或程序改用宽字符输入（wcin/_getws）。不影响功能主线。
